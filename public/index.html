05 — Questions & answers

A platform.
Clear boundaries.

How the ecosystem fits together, what the subscriptions are intended to cover and what is still in development.

What is Eyleme?

Eyleme is the shared brand and an independently usable open-source local task tool, with the ambition to grow into a community ecosystem. Derleme covers physical-world data collection and cloud or on-premises recording; Onama covers cybersecurity, authority, responsibility and regulatory workflows. The family is in development. First-party Eyleme core code and docs use Apache-2.0; Derleme and Onama are private-source products with planned paid subscriptions.

Read the public project scope
Do I need a subscription to use Eyleme?

No. The open-source Eyleme tool can be used independently, with its own permission checks. Paid Derleme and Onama subscriptions are intended for specialist field-data and governance needs. Packages, prices, service levels and launch availability have not been published, and this site has no subscription checkout.

Read the public project scope
Where will Derleme record field data?

The planned deployment options are cloud and on premises, within the customer’s own infrastructure. Derleme is intended to collect physical-world data with its source, timing and quality context. The actual connectors, storage setup and supported environment must be defined and accepted for each deployment. This is a product direction, not a claim that a customer installation is already available.

Explore the product family
What does Onama cover?

Onama focuses on cybersecurity, authorization, responsibility and regulatory compliance workflows: who may access data or act, under which policy, and how decisions and effects can be audited. It is a specialist product in development. Applicable requirements depend on the organization and deployment; the product does not itself provide legal certification or guarantee compliance. Eyleme’s basic local permission checks remain in the open-source core.

Explore the product family
What works today?

The core includes the task console and scoped native loop/model contracts, project-data gates, explicit-reference memory context, typed counter tools, reusable counter skills and decision evidence. Each component has its own proof and limits. This promotional site does not run them, and those proofs do not establish general inference, graph search or complete harness jobs.

Implemented components and evidence
Has real human authorization been demonstrated?

Yes, in a bounded native macOS counter demonstration: an actual device-owner check, exact approval, effective stop before the remaining action, revocation and state-preserving reopen passed on 14 October 2026. This grants no data-training or sharing rights. The separate start --human/browser flow, remote identity and arbitrary model jobs were not part of that acceptance.

Native person acceptance and limits
Does every job need nine models?

No. The optional roles are perception, reasoning, planning, decision, action policy, world model, specialist, critic and representation/retrieval. One model may fill several compatible roles. Audio, vision and text profiles are distinct, and exact model acceptance is required before execution.

Roles and binding contracts
Can I run local models or connect an external one now?

Declared model artifact and role contracts are implemented; they do not load weights or run inference. Local assignments still report unsupported execution. The architecture permits explicitly configured external frontier models, but configuration is not authorization to disclose private data or make paid calls. A local-only profile never silently falls back to a hosted model.

Model contract and unsupported execution
How do RAG, memory and the knowledge graph fit?

The design grounds answers in permitted project documents and optional working, episodic, semantic, procedural, knowledge-graph and analytical memory. The current Rust adapter builds bounded context from explicit source references, rechecking rights, expiry and lineage. Semantic/vector retrieval, graph traversal, analytical engines and tokenizer counting remain separate acceptance gates.

Implemented source context and memory limits
How are decisions explained?

Native decision evidence joins submitted alternatives, constraints and declared model pins to actual scoped tool receipts and complete, partial or unknown outcomes. Confidence and model declarations remain unverified inputs. The current proof uses deterministic counter tools; model explanations, causal claims and whole-loop performance require separate evidence.

Decision evidence and measured scope
Can private project data train or enter the ecosystem?

Not automatically. Execute, collect, train, external disclosure and ecosystem export are independent purposes. Derived records inherit current source restrictions; withdrawal blocks future use but does not erase published copies or unlearn weights. Ecosystem packages need explicit selection, provenance, terms, review and compatible import acceptance.

Project-private purpose and lineage gates
How will local learning work?

The plan accepts training per exact model: owned Rust gradients, CPU/Metal LoRA and separately supported QLoRA, followed by independent evaluation and controlled promotion. Unsloth-like tooling remains a reviewed reference or recipe aid with separate export/reacceptance gates. No accepted native training or improved-model result is claimed.

Native improvement and acceptance
Which platform comes first?

The first experimental target is a single-user loopback application on a MacBook Pro with Apple M4 Pro and 24 GB unified memory. Browser and native execution have distinct boundaries. Mac mini M4 and Linux RTX equipment are additional inventory, not accepted support; remote access and Linux acceptance are future scope.

Accepted scope and hardware inventory
What is the project license?

Eyleme first-party core code and documentation use Apache-2.0. Separately identified third-party material, model weights and datasets retain their own terms. This does not grant a blanket license to every asset or model, or change the website repository license.
